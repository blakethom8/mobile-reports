Phase 2: Agent Core — Technical Specification

Prepared by Chief | March 10, 2026

Enterprise Assistant  |  The brain that turns an API into an agent

ℹ️ What This Is: Complete specification for the agent core — the LLM reasoning loop that takes user messages, loads context from OneDrive, executes tools via Graph API, and maintains conversation memory. This is what makes the Enterprise Assistant an actual assistant.

SECTION A — Architecture Overview

1. The Agent Loop

The agent follows the same pattern as OpenClaw's Pi harness: a while loop that calls the LLM, checks for tool calls, executes them, and loops back until the LLM returns a final text response.

SECTION B — Database Schema

3. PostgreSQL Tables

-- Conversations
CREATE TABLE conversations (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id     TEXT NOT NULL,          -- AAD user email or OID
    title       TEXT,                   -- Auto-generated from first message
    created_at  TIMESTAMPTZ DEFAULT now(),
    updated_at  TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX idx_conversations_user ON conversations(user_id);

-- Messages (full conversation history)
CREATE TABLE messages (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    conversation_id UUID REFERENCES conversations(id) ON DELETE CASCADE,
    role            TEXT NOT NULL CHECK (role IN ('user', 'assistant', 'system')),
    content         TEXT,               -- Text content
    tool_calls      JSONB,              -- Claude tool_use blocks (if role=assistant)
    tool_results    JSONB,              -- Tool execution results (if role=tool)
    model           TEXT,               -- Model used (e.g. claude-sonnet-4-20250514)
    tokens_in       INTEGER,
    tokens_out      INTEGER,
    created_at      TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX idx_messages_conversation ON messages(conversation_id, created_at);

-- User context (long-term memory, preferences)
CREATE TABLE user_context (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id     TEXT NOT NULL,
    key         TEXT NOT NULL,          -- e.g. 'preference.timezone', 'memory.project_x'
    value       TEXT NOT NULL,
    updated_at  TIMESTAMPTZ DEFAULT now(),
    UNIQUE(user_id, key)
);

CREATE INDEX idx_user_context_user ON user_context(user_id);
✅ Design Choice: Conversation history in PostgreSQL, not OneDrive. Fast queries, proper indexing, no file locking issues. OneDrive is for user-facing files (AGENT.md, reports). PostgreSQL is for agent internals (memory, history, state).

SECTION C — Tool Definitions

4. Tools for Claude

Each tool maps directly to a method on our existing Graph clients. The tool registry defines the Claude tool schema and dispatches execution.

Tool NameDescriptionMaps To
list_emailsList recent emails from inbox or folderEmailClient.list_emails()
get_emailGet full email content by IDEmailClient.get_email()
search_emailsSearch emails by keywordEmailClient.search_emails()
draft_emailCreate a draft email (never auto-send)EmailClient.create_draft()
list_eventsList upcoming calendar eventsCalendarClient.list_events()
create_eventCreate a calendar eventCalendarClient.create_event()
find_available_slotsFind free time on calendarCalendarClient.find_available_slots()
read_fileRead a file from OneDriveFilesClient.read_file()
write_fileWrite/update a file on OneDriveFilesClient.write_file()
list_filesList files in a OneDrive folderFilesClient.list_folder()
search_filesSearch OneDrive files by name/contentFilesClient.search_files()
🚨 Safety Rule — No Auto-Send: The agent can DRAFT emails but never send them automatically. The send_email method exists in EmailClient but is NOT exposed as a tool. Sending requires explicit user confirmation through a separate flow (future Phase 3 web UI feature).

SECTION D — Agent Core Modules

6. llm.py — Claude API Client

Thin synchronous wrapper around the Anthropic Python SDK. Keeps LLM concerns isolated from agent logic.

  • Class: ClaudeClient
  • Constructor: Takes API key, model name (default: claude-sonnet-4-20250514), max_tokens (default: 4096)
  • Method: chat(system, messages, tools=None) → response
  • Returns the raw Anthropic response object (content blocks, stop_reason, usage)
  • Uses anthropic.Anthropic (synchronous client)
  • Dependency: anthropic Python package (add to requirements.txt)

7. tools.py — Tool Registry

Central registry that maps tool names to their Claude schema definitions and execution functions.

  • Class: ToolRegistry
  • Constructor: Takes email_client, calendar_client, files_client, default_user
  • Method: get_tool_definitions() → list[dict] — returns all tool schemas for Claude
  • Method: execute(tool_name, tool_input) → str — dispatches to the right client method, returns result as string
  • Each tool execution is wrapped in try/except — errors return a user-friendly error string (not a crash)
  • Tool results are JSON-serialized for Claude to consume

8. prompt.py — System Prompt Builder

Assembles the system prompt from OneDrive workspace files and runtime context.

  • Function: build_system_prompt(agent_md, user_md, skills, current_time, user_email) → str
  • Loads AGENT.md content (identity, rules, personality)
  • Loads USER.md content (user preferences, context — if it exists)
  • Appends available skill descriptions
  • Adds current date/time and user email
  • Adds safety rules (never send email without confirmation, never delete without confirmation, label external content as untrusted)

Default System Prompt Structure

You are an AI executive assistant for {user_email}.
Current time: {current_time}

## Identity
{AGENT.md content — or default if not found}

## About Your User
{USER.md content — or "No user profile configured yet."}

## Available Tools
You have access to the following tools:
{skill descriptions — one line each}

## Rules
- NEVER send emails automatically. Only create drafts.
- NEVER delete files or emails without explicit confirmation.
- When creating calendar events, confirm details first.
- Be concise and direct. Executives are busy.
- If you're unsure, say so. Don't hallucinate.

9. workspace.py — OneDrive Workspace Reader

Reads agent configuration files from the user's OneDrive /Assistant/ folder.

  • Class: WorkspaceReader
  • Constructor: Takes files_client, user_email
  • Method: load_agent_md() → str | None — reads /Assistant/AGENT.md
  • Method: load_user_md() → str | None — reads /Assistant/USER.md
  • Method: load_skills() → list[dict] — lists /Assistant/skills/, reads each SKILL.md
  • All reads are fail-safe — returns None/empty if files don't exist (OneDrive not provisioned, files not created yet)
  • Caches loaded content for the duration of a conversation (don't re-read on every turn)

10. memory.py — Conversation Memory

PostgreSQL-backed conversation storage. Handles creating conversations, appending messages, and loading history for context.

  • Class: ConversationMemory
  • Constructor: Takes db connection (from postgres.py)
  • Method: create_conversation(user_id, title=None) → conversation_id
  • Method: add_message(conversation_id, role, content, tool_calls=None, tool_results=None, model=None, tokens_in=None, tokens_out=None)
  • Method: get_messages(conversation_id, limit=50) → list[dict] — returns messages in chronological order
  • Method: get_recent_conversations(user_id, limit=10) → list[dict]
  • Method: format_for_claude(conversation_id) → list[dict] — converts stored messages into Claude's message format (handling tool_use/tool_result blocks properly)

11. loop.py — The Agent Loop

The main orchestrator. This is the heart of the agent.

  • Class: AgentLoop
  • Constructor: Takes claude_client, tool_registry, workspace_reader, conversation_memory
  • Method: run(user_message, user_email, conversation_id=None) → AgentResponse

Agent Loop Pseudocode

def run(user_message, user_email, conversation_id=None):
    # 1. Get or create conversation
    if not conversation_id:
        conversation_id = memory.create_conversation(user_email)
    
    # 2. Load context (cached per conversation)
    agent_md = workspace.load_agent_md()
    user_md = workspace.load_user_md()
    skills = workspace.load_skills()
    
    # 3. Build system prompt
    system = build_system_prompt(agent_md, user_md, skills, now(), user_email)
    
    # 4. Load conversation history
    messages = memory.format_for_claude(conversation_id)
    
    # 5. Append user message
    messages.append({"role": "user", "content": user_message})
    memory.add_message(conversation_id, "user", user_message)
    
    # 6. Agent loop (max 10 iterations to prevent runaway)
    for i in range(10):
        response = claude.chat(system, messages, tools=tool_registry.get_tool_definitions())
        
        # 7. Check for tool calls
        tool_calls = [b for b in response.content if b.type == "tool_use"]
        
        if not tool_calls:
            # 8. Final text response
            text = "".join(b.text for b in response.content if b.type == "text")
            memory.add_message(conversation_id, "assistant", text,
                             model=response.model, 
                             tokens_in=response.usage.input_tokens,
                             tokens_out=response.usage.output_tokens)
            return AgentResponse(text=text, conversation_id=conversation_id)
        
        # 9. Execute tools
        memory.add_message(conversation_id, "assistant", None, 
                         tool_calls=[tc.model_dump() for tc in tool_calls])
        
        messages.append({"role": "assistant", "content": response.content})
        
        tool_results = []
        for tc in tool_calls:
            result = tool_registry.execute(tc.name, tc.input)
            tool_results.append({
                "type": "tool_result",
                "tool_use_id": tc.id,
                "content": result
            })
        
        messages.append({"role": "user", "content": tool_results})
        memory.add_message(conversation_id, "system", None, 
                         tool_results=tool_results)
    
    # 10. Safety: max iterations reached
    return AgentResponse(text="I got stuck in a loop. Could you rephrase?",
                        conversation_id=conversation_id)

SECTION G — Implementation Notes

15. Key Constraints

  1. Synchronous only — no async/await. Use anthropic.Anthropic (sync), psycopg2 (sync), requests (sync). FastAPI handles the threading.
  2. No msgraph-sdk — we use raw requests via our GraphAuth class. Already built.
  3. OneDrive may not exist yet — all workspace reads must gracefully handle 404s. Use default system prompt if AGENT.md doesn't exist.
  4. PostgreSQL connection — use connection pooling. Create tables on startup if they don't exist (idempotent schema init).
  5. Tool results as strings — all tool execution results should be JSON-serialized strings for Claude. Keep them concise (truncate email bodies to ~500 chars in list views).
  6. Max 10 tool iterations — prevent runaway loops. Log a warning if we hit the limit.
  7. Error handling in tools — never crash the agent loop. Tool errors return a friendly error string that Claude can reason about.

16. What NOT to Build (Phase 2 Scope)

  • ❌ Web UI (Phase 3)
  • ❌ Teams bot (Phase 4)
  • ❌ Streaming responses (later optimization)
  • ❌ File upload/download (later)
  • ❌ Multi-user auth (single user for now, use DEFAULT_USER_EMAIL)
  • ❌ Send email tool (safety — drafts only)
  • ❌ Web search / fetch (Phase 2.5)

Conversation persists across requests via conversation_id. "What meetings do I have today?" returns your real calendar events.
