1. Executive Summary

The Goal: Transform a Mac Mini M4 into a dedicated, always-on AI agent server running OpenClaw, connected to your MacBook Pro via Tailscale, accessible from anywhere.

What This Achieves

  • Always-On Assistant: OpenClaw runs 24/7, handling Telegram messages, cron heartbeats, and background tasks even when your laptop is closed
  • Resource Separation: Heavy agent workloads (transcription, data analysis, multi-agent sessions) run on the Mini, keeping your MacBook fast and battery-efficient
  • Anywhere Access: Reach your agent server from coffee shops, hotels, or anywhere via Tailscale's encrypted mesh VPN
  • Local Intelligence: Unlike cloud VPS, the Mini sits on your home network with <1ms latency to local files and devices

2. Why a Mac Mini?

The Problem with Running OpenClaw on a MacBook

Resource Contention: On Blake's MacBook Pro M3 Max (48GB RAM), system profiling showed 43GB in use — Docker alone consumes 9.2GB, OpenClaw gateway 2.3GB. Running 4+ concurrent agents hits swap and slows everything down.

Key friction points:

  • Always-on vs daily-driver conflict: OpenClaw is most useful running 24/7 (Telegram at 3AM, heartbeats every 30 min), but you need to close your laptop and go places
  • Battery drain: Agent workloads (web research, transcription, multi-step analysis) peg the CPU and kill battery life
  • Thermal throttling: Whisper transcription of a 40-min podcast while working = noticeable performance hit
  • The uncomfortable truth: Your AI assistant is competing with Spotify for RAM. That's not good architecture.

Key Insight: A personal AI agent needs to be close to your personal data. Cloud instances work for serving web apps. Local machines work for running agents that interact with your files, messaging apps, and local tools.

4. Tailscale Networking Layer

What Tailscale Is (No Jargon)

Tailscale creates a private network just for your devices. Install the app on your MacBook and Mac Mini, log in with the same account, and they can talk to each other as if they're plugged into the same router — regardless of where they physically are.

The connection is:

  • Direct: Peer-to-peer, not through a central server
  • Encrypted: WireGuard protocol (excellent, modern crypto)
  • Persistent: Same IP address every time (e.g., 100.64.x.2), no matter what network you're on
  • Automatic: No manual config, no port forwarding, no DNS fiddling

How It Works: The 3-Layer Stack

Layer 1: WireGuard (The Encryption)

  • Modern VPN protocol (~4,000 lines of code vs OpenVPN's ~100,000)
  • Cryptography: Curve25519 (key exchange), ChaCha20-Poly1305 (encryption)
  • Connectionless (UDP), stealthy (doesn't respond to unknown sources)
  • What WireGuard does NOT do: discover peers, handle auth, traverse NATs

Layer 2: Tailscale (The Coordination)

  • Coordination server handles: key exchange, peer discovery, ACL enforcement
  • Your data never touches Tailscale's servers — only metadata (which devices exist, their endpoints)
  • Think of it as a "phone book" that tells your devices how to find each other

Layer 3: NAT Traversal (The Magic)

  • STUN: Discovers your public IP and NAT type
  • Hole punching: Both devices send UDP packets simultaneously, creating "holes" in their NAT routers
  • DERP relays: Fallback if direct connection fails (strict NATs, corporate firewalls)
  • Success rate: ~95% direct (peer-to-peer), ~5% relayed (still encrypted end-to-end)

Tailscale ACLs: Fine-Grained Access Control

{
  "acls": [
    {
      "action": "accept",
      "src": ["tag:laptop"],
      "dst": ["tag:agent-server:22,18789"]
    }
  ],
  "tagOwners": {
    "tag:laptop": ["autogroup:admin"],
    "tag:agent-server": ["autogroup:admin"]
  }
}

Translation: The laptop can reach the agent server on port 22 (SSH) and port 18789 (OpenClaw gateway). Nothing else. No other device on the tailnet can reach the Mini at all.

Cost: $0/month

  • Free tier: Up to 100 devices
  • All features including ACLs, MagicDNS, HTTPS
  • No bandwidth limits
  • Personal use = perfect fit

Mac Mini: openclaw.json

{
  "version": "2026.3.x",
  "auth": {
    "profiles": {
      "anthropic": {
        "provider": "anthropic",
        "apiKey": "sk-ant-..."
      }
    },
    "default": "anthropic"
  },
  "model": {
    "default": "anthropic/claude-sonnet-4-5",
    "fallbacks": ["anthropic/claude-opus-4-5"]
  },
  "workspace": {
    "path": "/Users/blake/openclaw/workspace"
  },
  "gateway": {
    "port": 18789,
    "mode": "local",
    "bind": "tailscale",
    "auth": {
      "mode": "token",
      "token": "GENERATE_NEW_UNIQUE_TOKEN_HERE"
    },
    "tailscale": {
      "mode": "userspace",
      "resetOnExit": false
    }
  },
  "contextPruning": {
    "mode": "cache-ttl",
    "ttl": 3600
  },
  "agents": {
    "maxConcurrent": 4,
    "subagents": {
      "maxConcurrent": 8
    }
  },
  "heartbeat": {
    "interval": 1800
  }
}
Key Differences from MacBook Config:
  • gateway.bind → "tailscale" (accessible over Tailscale, not just localhost)
  • gateway.tailscale.mode → "userspace" (enable Tailscale integration)
  • Generate a new, unique gateway token (don't reuse the MacBook's token)

MacBook Pro: openclaw.json

{
  "gateway": {
    "port": 18789,
    "mode": "local",
    "bind": "loopback",
    "tailscale": {
      "mode": "off"
    }
  }
}

Strategy: MacBook keeps its own local gateway for when you're working without the Mini. When you want to reach the Mini's gateway, you hit 100.64.x.2:18789 directly.

Auto-Start on Boot: Launch Agent

Create ~/Library/LaunchAgents/com.openclaw.gateway.plist on the Mac Mini:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" 
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.openclaw.gateway</string>
    <key>ProgramArguments</key>
    <array>
        <string>/opt/homebrew/bin/openclaw</string>
        <string>gateway</string>
        <string>start</string>
    </array>
    <key>RunAtLoad</key>
    <true/>
    <key>KeepAlive</key>
    <true/>
    <key>StandardOutPath</key>
    <string>/Users/blake/openclaw/logs/gateway-stdout.log</string>
    <key>StandardErrorPath</key>
    <string>/Users/blake/openclaw/logs/gateway-stderr.log</string>
</dict>
</plist>

Load it:

mkdir -p ~/openclaw/logs
launchctl load ~/Library/LaunchAgents/com.openclaw.gateway.plist

Step 2.1: Unbox Mac Mini, connect power + Ethernet to router

Step 2.2: Connect monitor + keyboard for initial setup (temporary)

System Settings:

8. Security Architecture

Defense in Depth: 4 Layers

┌─ LAYER 1: Tailscale Account ───────────────────────────────────┐ │ Only devices authenticated with your account can connect │ │ │ │ ┌─ LAYER 2: ACL Rules ──────────────────────────────────────┐ │ │ │ Only allowed device pairs, on allowed ports │ │ │ │ │ │ │ │ ┌─ LAYER 3: Application Auth ─────────────────────────┐ │ │ │ │ │ OpenClaw gateway requires token auth │ │ │ │ │ │ SSH requires key-based auth (no passwords) │ │ │ │ │ │ │ │ │ │ │ │ ┌─ LAYER 4: macOS Permissions ─────────────────┐ │ │ │ │ │ │ │ FileVault (disk encryption) │ │ │ │ │ │ │ │ Firewall (blocks incoming connections) │ │ │ │ │ │ │ │ macOS Gatekeeper, System Integrity Protection│ │ │ │ │ │ │ └───────────────────────────────────────────────┘ │ │ │ │ │ └──────────────────────────────────────────────────────┘ │ │ │ └────────────────────────────────────────────────────────────┘ │ └──────────────────────────────────────────────────────────────────┘

Why this matters: An attacker would need to breach ALL FOUR layers to access your agent's data.

What's Protected

  • ✅ Transport encryption (WireGuard)
  • ✅ Authentication (OAuth login to Tailscale)
  • ✅ Authorization (ACLs restrict which devices can talk)
  • ✅ No open ports on your router (NAT traversal magic)
  • ✅ Application-level auth (gateway token, SSH keys)
  • ✅ Data at rest (FileVault disk encryption)

What's NOT Protected

  • ⚠️ Device compromise: If someone gets root on your Mac Mini, game over
  • ⚠️ Tailscale account compromise: If someone gets your login, they can add devices
  • ⚠️ Physical access: Someone with physical access to the Mini can potentially extract data
  • ⚠️ Prompt injection: LLMs can't differentiate user input from malicious external data

Best Practices

  • Use a password manager with 2FA for your Tailscale account
  • Rotate the OpenClaw gateway token every 90 days
  • Keep macOS and OpenClaw updated (security patches matter)
  • Review Tailscale device list monthly (remove old/unused devices)
  • Don't expose the gateway to the public internet (Tailscale only)

9. Maintenance & Operations

Daily (Automated)

  • OpenClaw heartbeat runs every 30 minutes
  • Memory files appended to daily log
  • Docker containers cleaned up after use

Weekly (Manual, 5 minutes)

ssh blake@blakes-mac-mini

tail -50 ~/openclaw/logs/gateway-stderr.log

df -h

vm_stat | head -5

# Update macOS
softwareupdate --install --all

# Update Homebrew packages
brew update && brew upgrade

# Update OpenClaw
npm update -g openclaw

# Update Python tools
pip3 install --upgrade openai-whisper yt-dlp

# Clean Docker
colima ssh -- docker system prune -f

Troubleshooting

  1. SSH into Mini: ssh blake@blakes-mac-mini
  2. Check gateway: launchctl list | grep openclaw
  3. Check logs: tail -100 ~/openclaw/logs/gateway-stderr.log
  4. Restart gateway: openclaw gateway restart
  5. Nuclear option: sudo reboot (auto-start will recover)
