SECTION A — Vision & Core Architecture

1. What We're Building

A personal AI assistant for executive-level users that lives entirely inside their Microsoft 365 environment. Think of it as OpenClaw — Chief — but deployed per user, per org, in Microsoft's cloud.

The One-Sentence Pitch

"A personal Chief of Staff who lives in your Microsoft 365, knows your inbox, calendar, and files — works 24/7 — and never lets your data leave your environment."

2. Design Principles

PrincipleWhat It MeansWhy It Matters
One agent per user Each person gets their own isolated agent instance Tight personal context; no cross-user data risk
OneDrive as workspace Agent reads/writes to user's OneDrive folder Files appear on their laptop automatically via sync
Client's Azure tenant Code runs in their cloud, not yours Eliminates compliance/security gatekeeping
SKILL.md-driven tools Tools described in markdown, like OpenClaw skills LLM knows what tools exist and when to use them
Explicit permissions Every Graph API scope listed, admin-consented IT teams can audit, restrict, and revoke cleanly
Controlled web access Web-fetch sandboxed with injection protections Prevents prompt injection from external content

SECTION B — OneDrive Workspace Structure

4. The User's OneDrive Folder

The agent's entire workspace lives in one folder in the user's OneDrive. They can see it, edit it, and interact with it from their laptop — no special software needed. Microsoft's sync handles the rest.

~/OneDrive/
└── Assistant/
    │
    ├── AGENT.md          ← Who the agent is, its personality, rules
    ├── USER.md           ← Who the user is, their preferences, role
    ├── MEMORY.md         ← Long-term curated memory (agent maintains this)
    ├── WORK.md           ← Professional context, workflows, org knowledge
    ├── TOOLS.md          ← Tool-specific notes (contacts, aliases, shortcuts)
    ├── HEARTBEAT.md      ← Periodic check tasks (what to monitor proactively)
    ├── TODO.md           ← Task list (agent + user collaborate here)
    │
    ├── memory/           ← Daily logs (agent writes, user can read)
    │   └── YYYY-MM-DD.md
    │
    ├── skills/           ← SKILL.md files — tell agent what tools exist
    │   ├── email/SKILL.md
    │   ├── calendar/SKILL.md
    │   ├── files/SKILL.md
    │   ├── reports/SKILL.md
    │   ├── data/SKILL.md
    │   └── web/SKILL.md      ← allowlist-controlled web access
    │
    ├── reports/          ← Agent-generated reports (HTML, PDF)
    ├── drafts/           ← Email/doc drafts for user review before send
    └── context/          ← Reference files agent can read when needed
        ├── key-contacts.md
        ├── org-chart.md
        └── ongoing-projects.md
ℹ️ How files appear on the user's laptop: Microsoft OneDrive syncs automatically. When the agent writes a report to /Assistant/reports/ via Graph API, it appears in the user's local ~/OneDrive/Assistant/reports/ folder within seconds — no download needed.

10. Security Model for IT Stakeholders

The Three Questions IT Always Asks

Where does our data live? In your Azure tenant. We deploy inside your subscription. We never see it.

What can the app access? Exactly what your admin approves in Entra ID. Listed explicitly. Revocable instantly.

How do we audit it? Microsoft logs every Graph API call. Our app logs every agent action. Full visibility, always.

ℹ️ HIPAA note: Because everything runs in the client's Azure tenant, they inherit their existing Azure compliance certifications — HIPAA BAA, SOC 2, ISO 27001. We're not a new vendor in their data chain. We're code running in their already-certified environment.
