Codex vs OpenClaw vs Claude Code

Local architecture walkthrough of ~/.codex, ~/.openclaw, and ~/.claude — what each system stores, where the patterns overlap, and what we should learn for the enterprise agent.

Bottom line: these systems are converging on similar primitives — auth, config, sessions, skills, logs, memory/state, and project trust. The big difference is that OpenClaw has a real workspace philosophy, while Codex and Claude Code feel more like local coding runtimes with heavier internal state and thinner user-facing filesystem structure.

1. Executive Summary

Codex

A local coding-agent runtime with OAuth auth, SQLite-backed internal state, shell snapshots, sessions, skills, and automation tables.

OpenClaw

A broader personal-agent operating environment: gateway, channels, cron, devices, workspace files, memory DB, delivery queue, and agent orchestration.

Claude Code

A coding-agent environment with project transcripts, file history, session env snapshots, shell snapshots, todos, plugin metadata, and debug logs.

OpenClaw Agent operating system Workspace, messaging, proactive execution, orchestration "Personal/local agent platform"

6. Shared Architectural Patterns

All three systems independently converge on the same core ideas:

  • Auth is local and durable — tokens/identity live on disk.
  • Config is separate from runtime state — small editable config, larger managed state.
  • Sessions are persisted — transcripts and session artifacts survive restarts.
  • Shell/environment capture matters — both Codex and Claude snapshot shell context.
  • Skills/plugins/instruction packs are modular — capabilities are composable.
  • SQLite is a serious winner — especially for logs, jobs, run state, and memory indexes.
This matters for the enterprise agent: these are not random implementation details. They are emerging as the standard local architecture for serious tool-using agents.

7. Where Codex and Claude Code Are Similar

  • Both are clearly coding-agent-first, not general personal-agent systems.
  • Both keep project/session state locally.
  • Both snapshot shell or environment context.
  • Both maintain logs/debug data and some internal persistence that is more runtime-oriented than human-oriented.

8. Where OpenClaw Is Different

  1. Workspace-as-brain: OpenClaw makes the filesystem itself a first-class memory layer.
  2. Proactive runtime: cron, messaging, devices, delivery queue, paired nodes.
  3. Broader scope: OpenClaw is not just a coding tool — it is a local assistant platform.
  4. Human legibility: the most important knowledge is visible in markdown files, not hidden inside app state.

10. My Opinionated Take

If I had to rank the architectural ideas:

  1. OpenClaw has the best memory/workspace philosophy.
  2. Codex has the cleanest productized runtime/state split.
  3. Claude Code has strong project traceability and file/session operational patterns.

The ideal future system probably combines all three:

  • OpenClaw’s readable workspace and identity system
  • Codex’s internal state and automation architecture
  • Claude’s project/file history and session tracking rigor
